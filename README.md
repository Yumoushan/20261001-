# 稽查风险扫描与应对系统　使用说明

三个文件，各管一段：

| 文件 | 谁用 | 干什么 |
|---|---|---|
| `稽查风险扫描_客户版.html` | 发给客户 | 客户自己填数据，出风险清单。**不含任何处置方法** |
| `稽查风险扫描_顾问版.html` | 只你自己 | 同样的界面，多一个口令解锁的「顾问处置手册」 |
| `税务风险扫描与应对测算表.xlsx` | 只你自己 | 内部快速测算 + 45 条完整处置手册，可留底存档 |
| **在线版（部署链接）** | 客户扫码 | `https://tax-risk-scanner.app.workbuddy.host/` 同客户版，但支持**上传 Excel 自动解析** |

## 〇、在线版（扫码即用，A 版验证）

部署链接：**https://tax-risk-scanner.app.workbuddy.host/**

这是「客户版」的线上形态，比本地手填版多一个关键能力：**客户上传 Excel 报表，系统自动抽取科目填入表单**——不用客户一个个手填。

用法（给客户的话术）：
1. 把链接做成二维码（微信扫一扫或任意扫码工具）发给客户。
2. 客户打开后只填**企业名称 + 所属行业 + 纳税人类型**（就这三项，半分钟）。
3. 点「一键上传报表」→ 选他财务软件导出的 Excel（用友/金蝶财务报表、税务局申报表均可）。
4. 系统自动识别关键科目（营收、成本、应收、其他应收、存货、增值税、所得税等），按报表单位（元/万元）自动换算填入；**已抽到的表格会自动展开，没抽到的保持折叠**。
5. **税局申报表通常缺管理费用/销售费用/研发费用等利润表科目**——这些系统抽不到，客户点对应标题展开手动补一下即可；其他风险信息（逾期、欠税、关联交易等）也按需展开补充。
6. 客户点「开始扫描」，出风险清单（和本地版完全一致，不含任何处置方法）。**结果末尾会直接显示你的微信二维码，方便客户长按添加咨询。**

数据全程在客户浏览器里算，**不上传任何服务器**。SheetJS 解析库与 45 条规则引擎都跟着页面走，断网也能用（解析库已同目录内置）。

验证记录：用友科目余额表 / 金蝶标准报表 / 税局申报表 三种格式样例，自动抽取字段准确率 **100%**（元、万元单位均正确）。

### 咨询码：客户扫完，你不用等他重发文件

A 版没有后端，你看不到客户扫了什么。解决办法是「咨询码」——纯前端、零成本、数据只走微信：

1. **客户侧**：扫完出结果后，结果区多一个「生成咨询码（发给顾问）」按钮 → 点一下生成一长串编码 → 客户点「复制咨询码」（或「下载为文件」）→ 通过微信发给你。
2. **你侧（顾问版）**：打开 `稽查风险扫描_顾问版.html`，输入口令 `xiaoshan2026` 解锁后，页面顶部多一个「粘贴客户咨询码」卡片 → 把客户发来的码粘贴进去 → 点「还原客户数据并扫描」。
3. 系统自动把客户填报的全部数据填回表单、重新扫描，**风险清单 + 处置手册同步显示**——你立刻就能看到他上传了什么、扫出了哪些风险、每条怎么应对，客户无需重新发文件。

> 数据仅经微信在你与客户间传输（本来就要加微信），不经任何第三方服务器。客户版物理不含粘贴入口（F12 也翻不出），只有顾问版能还原。

**前往「设置—数据管理—应用」中管理**

## 一、客户版怎么用（发给客户）

双击打开就行，不用装任何东西，断网也能跑。也可以放到你自己的域名下做成一个链接。

客户只需先填**企业名称 + 所属行业 + 纳税人类型**；其余利润表、资产负债表、增值税/企业所得税申报数据、个税社保等表格**默认折叠**。

客户有两种填法：
- **推荐**：点「一键上传报表」，选财务软件导出的 Excel，系统自动抽科目并展开已填充的表格；抽不到的科目再手动补。
- **兜底**：手动点击各表格标题展开填写。金额单位统一是万元，比例填数字就行（20 就是 20%）。

填完点「开始扫描」，出来的是：

- 识别了多少个风险点，高中低各多少，综合评级
- 每个风险点的等级、可能被认定成什么、潜在影响有多大
- 底部一句话：**建议委托持证专业人员出具具体处置方案**

点「导出客户版报告」可以直接打印或存成 PDF。

**关键点：客户版里一个字的处置方法都没有。** 不是藏起来了，是根本没有——构建的时候就把那段代码物理删掉了，客户就算按 F12 看源码也翻不出来。

## 二、顾问版怎么用（你自己）

和客户版一样的界面，多一块「顾问处置手册」。

口令：**xiaoshan2026**

改口令：编辑 `build_html.py` 第 6 行的 `PWD`，重新跑一次 `python build_html.py` 就会重新生成两个 HTML。

解锁后每一条风险点会展开：

- **处置步骤**：第一步做什么第二步做什么，按顺序排好
- **政策依据**：具体文号和条款
- **需准备的材料**：直接抄给客户去准备
- **升级条件**：什么情况该往外转（转税务师事务所 / 转律师）
- **对客户的表述建议**：这句话可以直接说，说了不会出事

## 三、Excel 怎么用（内部测算）

四个工作表：

1. **数据录入**——黄格子填数，所属行业选完会自动带出行业预警区间。表里预填了一组演示数据（成都某某机械制造），可以直接看效果，正式用之前整列清空。
2. **风险扫描结果**——45 条规则的自动判定。D 列红色=命中，黄色=关注。F 列的提示文字可以直接摘给客户。
3. **处置手册**——45 条的完整 SOP，和顾问版内容一样，适合留底和内部检索。
4. **行业基准**——10 个行业的税负率、毛利率、应纳税所得率参考区间。觉得属地口径不一样，直接改这张表，所有公式跟着变。

演示数据的扫描结果：命中 25 项、关注 1 项、未命中 16 项、不适用 3 项。

## 四、45 条规则覆盖什么

| 类别 | 条数 | 典型规则 |
|---|---|---|
| A 增值税 | 10 | 税负率偏离、开票收入与申报收入三方勾稽、未开票收入占比、长期留抵、进项转出不合规、简易计税滥用、发票频繁增版增量 |
| B 企业所得税 | 8 | 毛利率偏离、期间费用率异常、长亏不倒、所得率偏低、招待费广宣费超限额、研发加计匹配性、折旧年限、准备金未调增 |
| C 往来与资金 | 8 | 应收增速背离、预收长期挂账、其他应收款异常（股东借款）、其他应付款、存贷双高、存货成本倒挂、三年以上应付款、现金交易占比 |
| D 个税与社保 | 6 | 个税社保人数比对、社保基数低于工资、分红未代扣、劳务未代扣、报销替代工资、奖金股权激励未申报 |
| E 小税种与申报 | 5 | 印花税计税依据不足、房产税地价未并入、土地使用税漏报、逾期申报与欠税、发票增版增量 |
| F 优惠与资质 | 4 | 高新资质维持指标不达标、小微临界点操纵、核定征收滥用、税收洼地无商业实质 |
| G 票据与关联 | 4 | 大额服务费无成果、农产品成品油票占比、上下游非正常户、关联交易占比过高 |

## 五、三条底线

1. **阈值是经验值，不是法条。** 行业区间是从公开资料整理的参考值，不是税务机关正式公布的预警值。命中不等于一定有问题，只说明这个点值得看一眼。真正的判断要结合属地口径和企业业务实质。
2. **处置手册不外发。** 它一旦到了客户手上，你的服务就没有稀缺性了。客户要方法，就签委托。
3. **见到刑事苗头立刻停手。** 虚开、伪造、故意隐匿收入这类，第一时间转律师，不要在税务层面做任何"技术处理"。每条规则的升级条件都写清楚了什么时候该往外交。

## 六、改规则怎么改

规则库是 `rules.json`，45 条，每条字段：

```
id / cat / name / level / trigger（触发条件）/ finding（可能被认定）/ cost（量化代价）
basis（政策依据）/ sop（处置步骤数组）/ docs（材料清单）/ escalate（升级条件）/ client（对客户表述）
```

改完 `rules.json` 后跑两条命令重新生成：

```bash
python build_html.py     # 重新生成两个 HTML
python build_excel.py    # 重新生成 Excel
```

HTML 里的判定逻辑在 `app_template.html` 的 `CHECKS` 对象里，Excel 的判定逻辑在 `build_excel.py` 的 `STATUS` 字典里。**改阈值要两边同时改**，否则两个版本会给出不一样的结果。
